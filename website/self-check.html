Self-check

Definition

The self-check runs agents that were built with one known defect and asks whether the failure classifier names that defect. If it does, the label means what the documentation says. If it does not, the label is not ready to trust. Agreement is the share of runs where a root cause was reported and it matched the planted defect.

Why this helps you

A taxonomy can sound precise and still be wrong. Before you treat "recovery" as a reason to change your agent, you want evidence that the word "recovery" is attached to runs that really did fail to recover. The planted agents are that evidence. They also show the honest case: a defect that never triggers is counted as "none", not as a success of the classifier.

Try this

relai selfcheck --trials 5

The default suite is reliability, and the default timeout rate for this command is 0.3 when you do not pass one. --trials defaults to 3. Five trials match the other tables on this site.

What you should see

diagnosed root cause per agent, reliability suite, timeout rate 0.3
agent     planted      planning  tool_misuse  context  recovery  horizon  unclassified  none  agreement
--------  -----------  --------  -----------  -------  --------  -------  ------------  ----  ---------
naive     recovery     0         0            0        25        0        0             35    1.00
retry     (control)    0         0            0        1         11       0             48    0.80
guessing  planning     55        0            0        0         0        0             5     1.00
looping   context      0         0            55       0         0        0             5     1.00
careless  tool_misuse  0         60           0        0         0        0             0     1.00

precision by mode: context 1.00, planning 1.00, recovery 1.00, tool_misuse 1.00

How to read it

Each baseline follows the reference plan in the suite, then does one wrong thing.

  • naive never retries. Where a timeout appears, the root cause is recovery, 25 times. The other 35 runs met no timeout, so the defect never surfaced. Those are "none", and they are not counted against the classifier. Agreement on the runs that did get a label is 1.00.
  • retry is the control. It has no planted defect. The 11 horizon labels are real step-budget overruns caused by its retries. The one recovery label is a run that still failed. Agreement 0.80 is not a broken classifier. The control is not supposed to match a planted mode.
  • guessing answers from the guess field and never calls a tool. That is a planning failure, 55 times. The mental-math task expects 42, and the guess is 42, so those five runs pass and are counted as none.
  • looping retries faults, then repeats each successful call and ignores what it returned. That repeat after an observation is a context failure, 55 times.
  • careless first calls a tool named shell that the task never allowed. Every run is tool misuse, 60 out of 60.

Precision by mode is 1.00 for the four planted modes: when the classifier said planning, context, recovery, or tool misuse as a root cause on these agents, that is the defect that had been planted. Horizon is not in that precision line because no agent is planted to fail only by running too long. The control produces horizon labels as a side effect, and they are reported in its row.

A new failure mode is accepted in this project only with a trajectory fixture that shows when the rule fires and when it must stay silent. Unmatched failures stay unclassified. That is the same discipline the self-check is enforcing.

Easy to mix up

"none" is not "unclassified". Unclassified means the run failed and no rule explained it. "none" means no root cause was reported, usually because the run passed and the planted defect never came up. Also, agreement ignores those silent runs. An agreement of 1.00 with a large "none" column means the classifier was right when it spoke, and the fault often did not show up. Raise the timeout rate if you want the defect to surface more often.
