Reports

Definition

A report is a saved view of an experiment: the ranked table, the interval, the paired test, the failure counts, and the trajectory of every run. The terminal prints the short version. --html and --markdown write the long version. --store keeps it in SQLite so you can render it again later. --json prints the same summaries as JSON.

Why this helps you

The terminal is enough while you are trying a command. It is a bad place to leave the only copy. A saved run lets you reopen the steps of the one trial that failed, share the HTML file with someone who does not have the package installed, or list every experiment you have run this week. The HTML file is standalone. Opening it does not need a server.

Try this

relai run demo --store runs.db --html report.html --markdown report.md
relai report runs.db --list
relai report runs.db --html report.html

--experiment 1 picks an id from the list. Omit it and the report command loads the latest experiment. Add --json to relai run when you want the numbers in a program. Status lines such as "saved" and "wrote" go to standard error, so the JSON on standard output stays clean.

What you should see

On standard error, then the same demo table as the install page, then one list row. The timestamp is the moment the experiment was saved. This one is from a run in this repository:

relai: saved experiment 1 to runs.db
relai: wrote report.html

  1  2026-10-30T22:08:34+00:00  run                      suite=demo  variants=2  runs=6

The HTML file opens in a browser. It repeats the ranked table and the paired sentence, draws a bar for each failure mode, and lists every run with its steps and the evidence strings.

How to read it

SQLite keeps five kinds of rows: the experiment, its variants, each run's scores, each step, and each failure label. The full trajectory is also stored as JSON on the run, which is what the report renders. Deleting a variant deletes its runs. The database file is ordinary SQLite. runs.db in the repository root is gitignored, along with report.html, so a local run does not become a commit by accident.

JSON Lines is the other export, and it is a Python function rather than a CLI flag. write_jsonl(results, path) writes one run per line. read_jsonl reads them back. Use it when you want to stream runs into another tool.

The store does not keep your agent's private memory. It keeps the trajectory the recorder wrote. If a step was never recorded, it cannot appear in the report.

Easy to mix up

The HTML report and this documentation site are different files. report.html is one experiment. The site you are reading explains the tool. Also, relai report reads a database. It does not re-run the agents. If you change the agent and want new numbers, run relai run again.
