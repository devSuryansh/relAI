Definition

Agent Reliability Lab (relai) runs an AI agent several times, breaks its tools on a schedule you can repeat, and writes down every step. From that record it scores the run and names why a failed run failed.

Why this helps you

Most agent benchmarks keep one number: did the agent finish the task? That number hides the reason. One agent skips a tool it needed. Another calls a tool it was never given. A third repeats the same call after the answer already came back. A fourth gives up after a single timeout. Two of those agents can finish at the same rate and still be failing for different reasons.

If you already have an agent, this lab lets you keep the whole path, not only the finish line. You can see the cost, the time, how often a retry saved the run, and whether the agent succeeds every time or only sometimes. The same broken tool calls are handed to every agent you compare, so a higher score means that agent handled the failure.

The sidebar is the library. The numbers beside eight of the pages are a first visit: follow them once, in order. After that, open the page you need. Each page defines the word it introduces, shows a command, and shows the output that command produced in this repository.

Try this

From a checkout where relai is installed, run the scripted demo. It needs no API key and no network.

relai demo

What you should see

variant    success  95% CI        cost     latency  recovery  horizon
---------  -------  ------------  -------  -------  --------  -------
resilient  1.00     [0.44, 1.00]  $0.0030  0ms      1.00      4.3
brittle    0.33     [0.06, 0.79]  $0.0020  0ms      0.67      2.0

failure modes (resilient): none
failure modes (brittle): {'planning': 1, 'recovery': 1}

resilient vs brittle on 3 paired runs: resilient alone passed 2, brittle alone passed 0; McNemar p = 0.5000 (not significant)

How to read it

Three tiny tasks. The resilient agent plans, uses the tool it was given, and retries after a timeout, so it passes all three. The brittle agent guesses "Lyon" instead of searching, and it gives up after the weather tool times out, so it passes one task out of three. Success 0.33 is that one pass.

The column 95% CI is a confidence interval. With only three tasks it is very wide: brittle's interval runs from 0.06 to 0.79. The last line is a paired test. Resilient was the only one to pass two of the tasks, but three pairs are too few for the test to call that a real difference (p = 0.50). A later page runs the same idea on 60 pairs, and there the difference is sharp.

failure modes counts labels, not tasks. Brittle picked up one planning failure and one recovery failure. Resilient picked up none. Those words are defined on Failure modes.

Easy to mix up

relai demo plays two hand-written scripts against three fixed tasks. relai run demo is a different command: it loads the demo suite and runs the naive and retry baseline agents through real tool faults. The numbers will not match, and that is expected. The install page runs the second command.
