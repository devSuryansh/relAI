Definition

The glossary is the same vocabulary as the rest of the site, in one list. Each feature page defines a word where it first matters. This page is where you look it up again a week later.

Why this helps you

The lab uses a handful of words in a precise way. "Trial", "success", and "recovery" all sound like ordinary English, and in this project they are not. Using the project meaning keeps a comparison fair. If a word in a table is unfamiliar, it is here, and the page that uses it is linked from the sidebar.

Try this

Pick one row in a results table you do not yet trust, and find that word below. Then open the feature page linked from the definition and run the command printed there.

What you should see

A short definition, then the page or the command where the word is used. The list is alphabetical after the two words the whole lab is built on, agent and trajectory.

How to read it

Agent
Anything with a name and run(task) that returns a trajectory. Models, scripts, and hand-written policies all qualify. See the agent contract.
Baseline
An offline reference agent shipped with the lab: naive, retry, guessing, looping, or careless. Useful as the other row in a comparison when you do not want to call a model.
Bootstrap
A way to build a confidence interval by resampling. With several trials, relAI resamples whole tasks, because the trials of one task are not independent.
Call number
How many times this run has already called this tool, including the current call. The first call is 1. The counter is per tool, not per run. Faults are keyed by it.
Confidence interval
A range that expresses how sure the success rate is. The table prints a 95% interval. A wide interval means you do not have enough tasks or trials to be precise yet.
Consistency
The share of tasks whose trials all agree, either all passing or all failing. Printed as consistent.
Context failure
The agent repeated a tool call with the same arguments after it had already received an observation. It ignored new information.
Correctness
A number from 0 to 1 beside the pass/fail score. Most scorers use 0 or 1. The numeric scorer gives partial credit.
Fault
A timeout, an outage, or a fail-first-N miss, injected into a tool call. The schedule ignores which agent is running. See seeded faults.
Failure mode
One of planning, tool misuse, context, recovery, and horizon. A run may have several. See failure modes.
Horizon
The length of a run, in steps. A horizon failure means the run exceeded max_steps or stopped without a final answer. A correct answer can still be flagged.
McNemar test
A paired significance test. It uses only the runs where one agent passed and the other failed. The table prints the exact two-sided p-value. Below 0.05 the lab calls the difference significant.
Pareto front
The settings that are not beaten on every objective at once. Here the objectives are higher success, lower cost, and lower latency. A setting on the front is one you might actually choose.
pass@k
The chance that at least one of k sampled trials succeeds. Estimated as 1 - C(n - c, k) / C(n, k) from c successes in n trials, then averaged over tasks. This measures capability.
pass^k
The chance that all k sampled trials succeed. Estimated as C(c, k) / C(n, k). The table's pass^k column uses k equal to the number of trials. This measures dependability. See scores.
Planted defect
A baseline built so that one failure mode is the known correct diagnosis. The self-check uses these to see whether the classifier agrees.
Planning failure
A wrong answer with no environment error, often because required tools were never called.
Recovery
Getting back to a working path after an error step: a later successful call of the tool that failed, or a correct final answer. The recovery column is the share of error episodes that were restored.
Recorder
The object an agent uses to write steps and to call tools. env.recorder(task) returns one. Calls made any other way are invisible to the lab.
Root cause
The failure mode with the earliest evidence in the trajectory. Not the only mode on the run.
Run
One agent, one task, one trial. A suite with 12 tasks and 5 trials is 60 runs per agent.
Scorer
The function that compares the final answer with the task's expected text. One of exact, contains, normalized, numeric, or regex.
Seed
The integer that pins the fault schedule. The same seed, task, trial, tool, and call number always produce the same fault. --seed changes it. The default is 0.
Step
One entry in a trajectory. The kind is plan, tool_call, observation, error, recovery, or final. A step can carry latency, tokens, and cost.
Stress test
The same agents measured at several timeout rates, so you can see how fast success falls. The command is relai stress.
Success
The share of runs the scorer marked as passed. It is not the same as pass^k, and it is not the same as "no failure labels": a correct answer can still carry a horizon label.
Suite
A YAML or JSON file of tasks, tools, a scorer, and optional default faults. demo and reliability are built in.
Sweep
A grid of agent settings, each run on the same tasks and faults. The lab keeps the Pareto front and recommends the cheapest setting that meets a success target.
Task
One question the agent must answer: an id, a prompt, an expected answer, the tools it is allowed to call, tags, and an optional step budget.
Tool misuse
A call to a tool the task does not allow, or a failed call that is not an environment fault. Unknown tools and bad argument names count.
ToolEnv
The tools plus the fault policy for a suite. Agents receive one and call tools through its recorder.
Trajectory
The ordered list of steps in one run. Metrics and failure analysis read this list and do not call the agent again. See trajectories.
Trial
One attempt at a task. Trial numbers start at 0. Different trials see different faults, because the trial is part of the schedule.
Unclassified
A failed run that matched no failure mode. Left unlabeled on purpose.
Variant
One named agent in an experiment, optionally with a setting such as retry:3. Variants share the task list, the trial count, and the seed.
Wilson interval
The confidence interval used when each task is attempted once. It stays sensible when the success rate is 0 or 1, where a naive interval would not.

Easy to mix up

pass@k and pass^k are easy to swap because the names are close. The caret version, pass^k, is the strict one: every attempt must succeed. The @ version keeps a success if any attempt in the sample works. The printed column is pass^k.
