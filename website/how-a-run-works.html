How a run works

Definition

A run is one agent attempting one task one time. The harness may repeat that attempt. Each attempt returns a trajectory: the ordered steps of the attempt. Scores, costs, and failure labels are read from those steps afterward. They do not call the agent again.

Why this helps you

Once you can see the pieces, the rest of the site is a map rather than a pile of commands. Your own agent only has to fit one seam, name plus run(task). Everything else, the faults, the score, the comparison, stays outside the agent. That is what makes two agents comparable: they share the tasks, the trials, and the fault schedule, and they differ only in how they act.

Try this

This is the whole loop for the first task of the reliability suite, five times, with 30% of tool calls set to time out. Save it as a script, or paste it into python with the venv active.

from relai import FaultPolicy, Variant, load_suite, make_baseline, run_experiment

suite = load_suite("reliability")
env = suite.env(FaultPolicy(timeout_rate=0.3))
experiment = run_experiment(
    suite.tasks[:1],
    [Variant("naive", make_baseline("naive", env))],
    trials=5,
)
row = experiment.summary()[0]
print(suite.tasks[0].id, f"{row['success_rate']:.2f}", f"{row['pass_hat_k']:.2f}")

What you should see

order_status 0.80 0.00

The task asks for the status of order O-88121. The answer in the suite is "shipped".

How to read it

Walk the call from the inside out.

  1. load_suite reads a YAML file: the tasks, the fake tools, the scorer, and any default faults. "reliability" is a built-in name. A path to your own file works the same way.
  2. suite.env builds a ToolEnv: those tools plus a fault policy. The policy here times out about 30% of calls. The schedule depends on the seed, the task, the trial, the tool, and the call number. It does not depend on which agent is running.
  3. make_baseline("naive", env) builds an offline agent that follows the reference plan in the suite and gives up on the first failed call. Your agent will take the same env.
  4. run_experiment is the harness. For each selected task and each trial it stamps the trial number and the seed onto the task, calls agent.run, times the call, then scores, measures, and classifies the trajectory. If the agent raises, that attempt becomes a failed run with an error step. The experiment continues.
  5. The summary is one row per agent. 0.80 means four of the five trials passed. 0.00 is pass^k at k = 5: the chance that all five attempts succeed. One miss makes that chance zero. Success says the agent can do the task. pass^k says whether you can trust it to do the task every time.

The pieces that only read trajectories, and never call the agent, are the scorer, the metrics, the failure classifier, the confidence interval, the paired test, and the sweep. That split is what makes a result reproducible: replay the trajectory and you get the same labels.

Easy to mix up

A trial is not a task. The reliability suite has 12 tasks. --trials 5 attempts each task five times, which is 60 runs for one agent. Also, suite.tasks[:1] keeps only the first task. Drop the slice when you want the whole suite, which is what relai run reliability does.
