Your agent

The agent contract

Definition

The agent contract is two things: a string name, and run(self, task) -> Trajectory. Anything with those can be evaluated. New model backends, orchestrators, and memory systems adapt to that seam. They do not change the harness. Metrics and failure analysis read trajectories. They do not call the agent.

Why this helps you

You do not port your agent into a framework. You wrap the part that already calls tools. The wrapper's only job is to write steps and to let the lab's environment perform the tool calls. After that, trials, faults, scores, and reports apply without further integration. If you later swap the model, the wrapper stays, and old trajectories remain comparable.

Try this

Three shapes that already satisfy the contract. The first is the one you will write. The other two are included for tests and for tiny demos.

from relai import FunctionAgent, ScriptedAgent, Step, Task, Trajectory

def run(task: Task) -> Trajectory:
    return Trajectory(steps=[Step.final("42")])

wrapped = FunctionAgent("fn", run)

scripted = ScriptedAgent(
    "scripted",
    {"known": Trajectory(steps=[Step.final("yes")])},
    default=Trajectory(steps=[Step.final("no")]),
)

FunctionAgent adapts a plain function. ScriptedAgent returns a canned trajectory for each task id, and the default when the id is missing. Neither of them talks to tools. A useful agent takes a ToolEnv in its constructor and calls env.recorder(task), as on Plug in your agent.

What you should see

Nothing is printed. The two objects exist, and each has a name and a run method. Passing either one to run_experiment inside a Variant is enough for the harness to call it. A crash inside run does not crash the experiment: the harness records a single error step, marks the run failed, and continues with the next trial.

How to read it

What the harness promises you:

  • It calls run once per task per trial. The task is a copy. metadata["relai.trial"] and metadata["relai.seed"] are set.
  • It does not look at your constructor. Factories such as make_agent(env) are a CLI convenience, not part of the protocol.
  • It times the call from the outside. Tool latency you care about still has to be on the steps, which rec.call does for you.
  • It will not retry your agent for you. Retries are your policy, recorded as recovery steps and further calls.

What you promise the harness:

  • Return a trajectory, or raise. Do not return a bare string.
  • Put the answer in a final step if you have one.
  • Send tool calls through the recorder that belongs to this task. A recorder from a previous task still carries the previous fault counters.

The CLI spec for a factory is package.module:function, or a baseline name such as naive, retry:3, retry:max_retries=3,backoff_ms=10, guessing, looping, or looping:repeats=2. careless takes no extra parameter. An unknown name exits with code 2 and a one-line error on standard error.

Easy to mix up

The protocol is not a base class you must subclass. PolicyAgent is the base of the built-in baselines, and your agent can ignore it. Subclassing it is useful only when you want the reference plan and a place to change one behavior, which is how the planted-defect agents are written.
